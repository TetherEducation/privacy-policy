Privacy Policy - Tether: Campus Assistant

Last Updated: November 10, 2026

Version: 1.1.0

Overview

Tether: Campus Assistant is a browser extension developed by Tether Education. It lets staff of schools and school networks that use Tether's CRM or Tether's network dashboard sync a school's session on Anótate en la Lista, the Chilean Ministry of Education's public waiting-list registry (Registro Público Digital), with Tether, so that Tether can keep the school's waiting lists up to date.

Important: The extension works only together with Tether's web applications, for people who have a Tether account with access to the school. Without one, it does nothing. It is distributed through the Chrome Web Store.

What the Extension Does

A sync goes through these steps:

  1. In Tether (the CRM, or the network dashboard), you click "Sincronizar" for a school on the Anótate en la Lista integration page.
  2. The extension opens the registry's sign-in page in a new tab and types in the school's username and password, which are already saved in Tether.
  3. You solve the captcha and sign in.
  4. The extension reads the session the registry gives you, asks the registry which schools that account covers, hands the session to Tether for those schools, closes the tab and tells the Tether page that the sync is done.

The extension captures a session only when you ask it to, normally by starting a sync from Tether. If you open the registry on your own, it shows a notice and captures nothing.

Data the Extension Handles

What It Handles

  • The school's sign-in details for the registry (username and password)
    • Source: Tether's credential service, where the school's staff saved them. The extension requests them with your own Tether access, for the school you chose.
    • Use: Typed into the registry's sign-in form, so you do not have to.
    • Storage: Held in the sign-in tab's memory during the sync. Never written to the browser's storage, and not sent anywhere else.
  • The registry session (a session token)
    • Source: The registry's answer to your sign-in.
    • Use: Used once to ask the registry's API which schools (RBD codes) the account covers, then sent to Tether's services with those school codes.
    • Storage: Held in memory only. Never written to the browser's storage.
    • Transmission: To Tether's API endpoints, over HTTPS.
  • Your Tether access token
    • Source: The Tether page hands it to the extension when you start a sync.
    • Use: Authorizes the extension's requests to Tether's services as you, so Tether's own permissions decide what you may do.
    • Storage: Held in the extension's memory, tied to the sign-in tab, and discarded when that tab closes. Never written to the browser's storage.
  • Sync context
    • Service identifier (the registry)
    • School (campus) identifier and tenant code
    • The sign-in page's address, related settings and the time of the sync
    • Purpose: Tells the script on the sign-in tab which sync it belongs to, and routes the session to the right school.
    • Storage: In the browser's extension storage: the sync in progress in session storage, removed when it is read; and a record of the last sync's context in local storage, replaced by the next sync and removed once it is 30 minutes old the next time the extension reads it. It is not encrypted and holds no password and no token.
    • Transmission: None beyond the identifiers sent with the session.
  • Capture state
    • The phase of the sync in progress, the site and a timestamp
    • Storage: In memory only, until the sign-in tab closes.
    • Transmission: None (local only)
  • Diagnostic messages
    • The extension writes messages about its own operation to the browser's console.
    • Transmission: None (local only)

What It Does NOT Collect

  • ❌ Your own passwords. The only login it handles is the school's registry login described above.
  • ❌ Personal information (names, emails, addresses)
  • ❌ Waiting lists, applications or any applicant's or student's data
  • ❌ Browsing history
  • ❌ Cookies or content from other websites
  • ❌ Financial information
  • ❌ Any data from websites outside the sites listed under Permissions

What Tether Does With the Session

Once the extension has handed the session over, Tether's services use it to read the school's waiting lists on Anótate en la Lista. Those lists include applicants' names and identity numbers (RUN). That reading is done by Tether's services for the school, not by this extension, and is not governed by this policy.

How We Use Your Data

The data above is used exclusively to carry out the sync you started:

  1. Sign-in: Fill in the school's registry login for you
  2. Hand-over: Deliver the resulting session to Tether for the schools the account covers
  3. Status: Tell the Tether page and you whether the sync finished

We do NOT:

  • Sell or share data with third parties
  • Use data for advertising or marketing
  • Track your activity outside a sync
  • Keep data in the extension longer than a sync needs

Data Sharing

No data is shared with third parties. Data flows only between:

  • The extension (your browser)
  • The registry itself, where you sign in, and its API, asked once per sync which schools the account covers:
    • https://registropublicodigital.mineduc.gob.cl
    • https://apirpd.mineduc.cl
  • Tether's services:
    • Credential Manager API (https://api.v2.tether.education/crm-integrations/credentials)
    • Integration Core API (https://api.v2.tether.education/crm-integrations/core)
  • The Tether page where you started the sync, by messages inside that page:
    • Tether's CRM (https://app.tether.education/crm/campus-integration)
    • Tether's network dashboard (https://redes.tether.education)

All communication uses HTTPS.

Permissions Justification

The extension requests the following browser permissions. Each is needed for the sync described above:

Permission Purpose Justification
storage Keep the context of a sync Tells the script on the sign-in tab which sync it belongs to. Holds no password and no token. Uses chrome.storage.local and chrome.storage.session.
notifications Show how a sync went Displays desktop notifications about a sync, such as when a session has been captured and handed to Tether.
tabs Open and close the sign-in tab Opens the registry's sign-in page next to the Tether page, closes it when the sync finishes, sends the result to the Tether tab that started it, and discards the in-memory token when the sign-in tab closes.
scripting Run the sync's scripts Registers the capture script on the registry's site, puts the messaging script into Tether CRM pages that were already open when the extension was installed or updated, and reads the sync's progress to show it in the popup.

Security Measures

  • Nothing sensitive is stored
    • The school's login, the registry session and your Tether access token are held in memory only
    • They are never written to the browser's storage, and the tokens are discarded when the sign-in tab closes
  • Limited to declared sites
    • The extension's scripts run only on the sites listed above
    • Messages from a page are accepted only from that page's own origin
  • Your own permissions apply
    • The extension calls Tether's services with your own access, so it can do only what your Tether account may do for that school
  • HTTPS only
    • All communication uses HTTPS

Data Retention

Data Type Retention Period Deletion Method
School's registry login The duration of the sync Automatic (in memory only)
Registry session and Tether access token Until the sign-in tab closes Automatic (in memory only)
Sync context Until the next sync, or 30 minutes and the next read, or until the extension is uninstalled Automatic, or by uninstalling
Capture state Until the sign-in tab closes Automatic (in memory only)
Diagnostic messages Until the page or the browser closes Automatic (browser console only)
